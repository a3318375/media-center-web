**日期：** 2026-10-12

## 今天完成的工作

- 将 [PanSou](https://github.com/fish2018/pansou) 作为 Git submodule 固定在 API 仓库的上游 commit `221665fb2c9279f22af4684ea2d8c0c331eac1cc`，并只启用其 `main.go` 中实际启用的插件。

- 搜索缓存仍使用 PanSou 自带实现，数据放入媒体中心数据目录；集成了启动、异步插件注册、并发/超时限制、优雅关闭和磁盘缓存恢复。
- 增加子模块更新及生命周期补丁脚本，便于更新上游时重新生成插件注册表、应用必要补丁并执行构建/测试检查。
- 尚未修改前端页面，也没有改探索、详情、Provider 或 API 数据契约之外的功能。

## 当前实现范围与限制

当前默认加载 `5266ys`、`quark4k` 两个插件；虽然注册表按 PanSou 主程序中启用的清单生成（75 个插件），实际可用插件和资源占用受配置影响。可通过 `MEDIA_CENTER_PANSOU_PLUGINS` 调整启用列表。

这还是后端 PoC：没有资源搜索 UI，也没有对所有插件、长时间运行、并发压力或生产数据目录做完整验收。TG 搜索和真实提取码结果仍需补测。PoC 通过后再开始正式前端接入。

## 上游更新方式

API 仓库用 submodule 固定 PanSou 版本。初始化检出时执行 `git submodule update --init --recursive`；更新上游使用 API 仓库中的 `scripts/update-pansou.ps1`。脚本会更新 submodule、核对启用插件清单、应用可重放的最小生命周期补丁，并运行 Go 构建/测试。更新结果仍需要人工检查差异并提交新的 submodule 指针。
